# CI quality gates

- This fork validates changes locally first. Automatic CI execution on pull requests and pushes to `main` has been removed; `.github/workflows/ci.yml` runs only when explicitly requested with `workflow_dispatch`. Opening or merging a pull request does not establish a hosted CI pass.
- For full hosted validation, select **Actions → CI → Run workflow**, choose the branch to validate, and record the run URL and tested commit. The four existing checks keep their names, commands, and ten-minute job timeouts: **Check**, **Test**, and **Release Smoke** use `ubuntu-latest`; **Mobile Native Static Analysis** uses `macos-latest`.
- These standard GitHub-hosted runners replace inherited Blacksmith labels that this fork cannot use. The macOS job still installs `apps/mobile/Brewfile` before running native analysis: SwiftLint supports Apple Silicon, and Homebrew installs the Java dependencies for ktlint and detekt. No custom runner service or credentials are needed.
- For a smaller Rooms test/typecheck scope, select **Actions → Rooms Focused → Run workflow**. `.github/workflows/rooms-focused.yml` remains manual-only on `ubuntu-latest`; its commands and twenty-minute timeout are unchanged. This focused run does not establish that the full CI suite passed.
- Standard GitHub-hosted runner minutes are [free for public repositories](https://docs.github.com/en/actions/concepts/billing-and-usage). Manual execution limits unnecessary hosted work. Private repositories use their account's Actions allowance; artifact and cache storage have separate billing rules. Standard runners have fewer resources than the inherited custom runners, so hosted duration within the retained timeouts must be verified when CI is next requested.
- `.github/workflows/release.yml` builds macOS (`arm64` and `x64`), Linux (`x64`), and Windows (`x64`) desktop artifacts from a single `v*.*.*` tag and publishes one GitHub release.
- The release workflow auto-enables signing only when platform credentials are present. macOS passkey builds additionally require `APPLE_TEAM_ID` and the `MACOS_PROVISIONING_PROFILE` secret; Windows uses Azure Trusted Signing. Without the core signing credentials, it still releases unsigned artifacts.
- See [Release Checklist](./release.md) for the full release/signing setup checklist.
